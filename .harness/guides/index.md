# Harness guides

Read this once per task. Open only the guide your task needs: `.harness/guides/<name>/GUIDE.md`,
then only the references that guide links to.

| Guide | Use when | Open |
| --- | --- | --- |
| adr | A decision is hard to reverse: framework, database, external service, auth, public contract, data model, module boundary, build, deploy, security. | .harness/guides/adr/GUIDE.md |
| context | Start of a normal or larger task: read the soul and only the map area it touches; or set up docs/context. | .harness/guides/context/GUIDE.md |
| cto-review | Opening a pull request, writing an ADR, a grande or riesgoso change, or when the person asks for a CTO or architecture review. | .harness/guides/cto-review/GUIDE.md |
| docs | A change alters visible behavior: a CLI flag or output, an API, a config key, an install step, or a documented number or limit. | .harness/guides/docs/GUIDE.md |
| greenfield | A new or half-started project, after init --new: inventory what exists, interview, context, stack ADR, the fixed minimum and a first commit. | .harness/guides/greenfield/GUIDE.md |
| playbooks | A normal or larger task, once its level is set: the steps in order for a feature, bug, refactor, dependency, migration, release or incident. | .harness/guides/playbooks/GUIDE.md |
| roles | Designing a feature or an architecture choice, or a decision needs evidence, a critic or questions to the person (the grill). | .harness/guides/roles/GUIDE.md |
